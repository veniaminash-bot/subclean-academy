# Как опубликовать SUBCLEAN Academy на academy.subclean.ru

Здесь три файла:

- `index.html` — сама страница (весь дизайн, модули, тест, админ-панель)
- `app.js` — логика, которая подключается к базе данных
- `supabase-schema.sql` — команда для создания базы данных

Ничего программировать не нужно — только копировать/вставлять по шагам ниже. Займёт 15–20 минут.

---

## Шаг 1. Создать базу данных (Supabase)

1. Откройте **[supabase.com](https://supabase.com)** → **Start your project** → зарегистрируйтесь (можно через Google).
2. **New project**: название — например `subclean-academy`, придумайте и сохраните пароль базы данных (он не понадобится дальше, но пусть будет записан на всякий случай), регион — ближайший (Frankfurt подойдёт). Нажмите **Create new project** и подождите 1–2 минуты, пока проект создастся.
3. Слева в меню откройте **SQL Editor** → **New query**.
4. Откройте файл `supabase-schema.sql` (из этой папки), скопируйте **всё содержимое** и вставьте в редактор.
5. Нажмите **Run** (или Ctrl+Enter). Внизу должно появиться "Success. No rows returned".

Это создало все таблицы и два стартовых аккаунта: `VENIAMIN` / `SUBCLEAN` (администратор) и `test` / `test` (клинер).

## Шаг 2. Взять ключи подключения

1. В Supabase слева внизу — **Project Settings** (шестерёнка) → **API**.
2. Скопируйте два значения:
   - **Project URL** (выглядит как `https://xxxxxxxxxxxx.supabase.co`)
   - **anon public** ключ (длинная строка под "Project API keys")
3. Откройте файл `app.js` из этой папки в любом текстовом редакторе (подойдёт даже Блокнот).
4. В самом начале файла замените:
   ```
   var SUPABASE_URL = 'ВСТАВЬТЕ_URL_ПРОЕКТА_SUPABASE';
   var SUPABASE_ANON_KEY = 'ВСТАВЬТЕ_ANON_КЛЮЧ_SUPABASE';
   ```
   на свои значения (в кавычках). Сохраните файл.

## Шаг 3. Разместить сайт (Vercel)

Сайт уже опубликован и подключён к репозиторию **github.com/veniaminash-bot/subclean-academy** — Vercel автоматически пересобирает и публикует сайт при каждом обновлении кода в ветке `main`. Загружать папку вручную больше не нужно.

Временный адрес: **https://academy-site-kappa.vercel.app/**

Как обновляется код дальше: Клод меняет файлы → коммитит и отправляет (`git push`) в репозиторий на GitHub → Vercel сам видит изменение и публикует новую версию за минуту, без вашего участия. Тексты модулей, тест и список пользователей на это не влияют — они хранятся в базе данных Supabase отдельно от кода и при обновлении сайта не сбрасываются.

*(Если когда-нибудь понадобится развернуть сайт с нуля на новом аккаунте Vercel — тогда актуален способ через vercel.com/new с перетаскиванием папки, как раньше.)*

## Шаг 4. Подключить домен academy.subclean.ru

1. В проекте на Vercel откройте вкладку **Settings → Domains**.
2. Введите `academy.subclean.ru` → **Add**.
3. Vercel покажет запись, которую нужно добавить, обычно такого вида:
   ```
   Тип:  CNAME
   Имя:  academy
   Значение: cname.vercel-dns.com
   ```
4. Зайдите в панель управления вашим доменом `subclean.ru` (там же, где вы его покупали) → раздел **DNS**.
5. Добавьте новую запись с типом **CNAME**, именем **academy**, значением — тем, что показал Vercel.
6. Сохраните. DNS обновляется от нескольких минут до пары часов. Vercel сам покажет зелёную галочку, когда домен подключится.

После этого сайт будет доступен по адресу **academy.subclean.ru**. Ваш основной сайт на Тильде (subclean.ru) это никак не затронет.

## Шаг 5. Проверка

1. Откройте `academy.subclean.ru`, войдите как `VENIAMIN` / `SUBCLEAN`.
2. Проверьте, что видна **«⚙ Админ-панель»** в левом меню.
3. Откройте эту страницу в режиме инкогнито (или на телефоне) и войдите как `test` / `test` — админ-панели быть не должно, только обучение.
4. В обычном окне (под VENIAMIN) отредактируйте какой-нибудь текст модуля и сохраните.
5. Обновите страницу под `test` (или на телефоне) — изменения должны быть видны. Это и есть проверка, что данные теперь общие, а не только в одном браузере.

## Важно сделать сразу после запуска

- **Смените пароль администратора.** Зайдите в «⚙ Админ-панель» и поменяйте пароль `SUBCLEAN` на свой собственный — сейчас он стандартный и известен всем, кто видел этот код.
- Создайте отдельные учётные записи для реальных клинеров вместо `test`/`test`, или используйте `test` как временный демо-доступ.

## Что важно понимать про безопасность

Это внутренний инструмент для команды, а не публичный сервис с конфиденциальными данными:

- Пароли сотрудников **видны текстом** в админ-панели (не скрыты звёздочками при просмотре списка) — это сделано для простоты, не для банковского уровня защиты.
- Ключ `anon` в `app.js` — не секрет, он обязан быть в коде страницы; данные защищены не им, а тем, что все операции идут через функции базы данных, проверяющие права (описаны в `supabase-schema.sql`).
- Для полноценной защищённой системы аккаунтов (со скрытыми паролями, восстановлением доступа по почте и т.д.) нужна более серьёзная разработка — при необходимости это отдельная задача.

## Если что-то не работает

Самая частая причина — не вставлены или неверно вставлены `SUPABASE_URL` / `SUPABASE_ANON_KEY` в `app.js`, либо не выполнен `supabase-schema.sql`. Проверьте оба шага заново. Если не получается — пришлите мне, что видите на экране, разберёмся.
